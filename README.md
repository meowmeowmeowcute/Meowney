# Meowney 記帳

Meowney 是單一使用者使用的本機離線記帳工具。資料只儲存在目前瀏覽器的 IndexedDB，不會連線到後端、雲端或追蹤服務。

## 使用方式

以 HTTPS 靜態網站部署，或在本機透過 `http://localhost` 開啟 `index.html`。首次成功開啟後，Service Worker 會快取應用殼層；之後離線仍可進行記帳、借貸與部分結清、查詢、管理帳戶與類別，以及 JSON／CSV 的本機操作。

首次使用時沒有帳戶，請先從「設定」建立帳戶。系統只會建立少量母類別，不會自動建立子類別。

新增收入只需填寫金額、帳戶、日期與時間（備註可選），不需要選擇母類別或子類別。支出仍須選擇子類別，唯「其他」母類別可直接選取並記錄支出。支出可勾選「預計請款」，交易列會顯示此小標籤。在「查詢」選擇「尚未請款」後，可取消勾選不應報銷的項目、填寫共用備註，再「建立合併報銷」：系統會立即新增一筆金額等於所選項目合計的報銷收入。列表固定顯示「合併請款」，點開後才以條列呈現每個項目與金額；共用備註亦在明細中顯示。所選項目必須同屬一個帳戶；如有不同帳戶，先用帳戶條件分開建立即可。支出選擇「新增報銷」時，會以同帳戶、同日期時間建立一筆連動收入，並在儲存時自動取消原支出的預計請款與請款單；報銷金額預設帶入支出金額，但可獨立填寫部分報銷，之後也能單獨修改。報銷備註預設為原支出備註，且可個別改寫。交易紀錄會完整顯示每筆已填寫的備註；「其他」支出、收入與報銷都會優先以備註作為事項名稱；報銷有備註時，後方會保留灰色「報銷」標示，沒有備註才只顯示「報銷」。

若支出只有部分由自己付款，可在「更多設定」選擇「我欠別人」或「別人欠我」，填寫部分金額，並直接以備註記錄對象。「我欠別人」只先扣自己已付的部分；「別人欠我」會先扣完整付款，但支出統計只計自己的部分。沒有消費的借錢或借款則直接選「借貸」：借入選「我欠別人」，借出選「別人欠我」。紀錄頁會集中顯示未結清合計；點入原項目即可分次登記還款或收款。借貸現金流會更新帳戶餘額，但不會重複算成收入或支出。

## 備份與復原

- 在「設定」使用「匯出 JSON」建立完整備份。此檔包含帳戶、類別、交易、轉帳、設定、格式版本與匯出時間。
- 「還原 JSON」會先驗證檔案，並在確認後**完整覆蓋**目前資料。驗證失敗或取消確認都不會變更資料。
- 卸載 PWA、清除瀏覽器網站資料或重設裝置可能造成資料遺失；請保留 JSON 備份在自己可控的位置。

## CSV 標準

CSV 匯出使用 UTF-8（含 BOM）、CRLF 換行與 RFC 4180 式雙引號跳脫。欄位順序固定如下：

`交易識別、類型、金額、帳戶ID、帳戶、來源帳戶ID、來源帳戶、目的帳戶ID、目的帳戶、母類別ID、母類別、子類別ID、子類別、日期、時間、備註、報銷支出交易ID、預計請款、請款單ID、請款備註、合併報銷、借貸方向、借貸金額、借貸來源交易ID`

CSV 匯入會先預覽新增、跳過、建立帳戶、建立母／子類別與衝突筆數；使用者確認後才以單一資料庫交易寫入。規則如下：

- 既有交易 ID 且內容完全相同：跳過。
- 既有交易 ID 但內容不同，或 CSV 內重複交易 ID：視為衝突，整批不寫入。
- 缺少帳戶：依 CSV 帳戶名稱建立，初始餘額為 `0`。
- 缺少類別：依母類別與子類別名稱建立必要結構。
- 格式、資料型別、轉帳帳戶或母子類別關聯任一錯誤：整批不寫入。

無類別收入與獨立借貸的「母類別ID、母類別、子類別ID、子類別」四欄必須都留白；「其他」直接支出保留母類別欄位，子類別 ID 與名稱欄位留白；其餘支出與仍帶有歷史類別的收入則維持完整的母／子類別欄位。「預計請款」只接受一般支出的「是」；「請款單ID」與「請款備註」僅保留舊格式相容性，其他情況須留白。單筆報銷在「報銷支出交易ID」填一個原支出 ID；合併報銷以 `|` 連接原支出 ID、在「合併報銷」填「是」，且金額必須等於所有原支出合計。借貸方向使用 `payable` 或 `receivable`；還款／收款須在「借貸來源交易ID」保留原項目。關聯不完整或不一致時 CSV 會整批拒絕匯入。舊版 16、17、18、20 與 21 欄標準 CSV 仍可匯入。

CSV 中的帳戶與類別 ID 優先用於保留本應用程式自己匯出的關聯；當 ID 不存在時，才以名稱尋找或建立項目。帳戶、母類別，或同一母類別下的子類別若有同名而無法唯一判定時，會視為衝突並拒絕整批寫入。

## 部署與更新

部署時保留以下檔案及目錄：`index.html`、`styles.css`、`app.js`、`data-layer.js`、`query-logic.js`、`backup-format.js`、`service-worker.js`、`manifest.webmanifest`、`icons/`。

必須使用 HTTPS（`localhost` 開發環境除外），才能符合可安裝 PWA 的瀏覽器條件。每次發布有變動的應用殼層資源時，請遞增 `service-worker.js` 的 `CACHE_NAME`；新版會在背景準備，開啟下一次頁面時使用新資源，不會強制重新載入正在輸入的頁面。Service Worker 不會快取或傳送 IndexedDB 內的財務資料。

### GitHub Pages 發布

1. 在 GitHub 建立 repository，將本專案檔案上傳；不要上傳 `node_modules/`。
2. 到 repository 的 **Settings → Pages**，將來源設為 `main` 分支的 `/ (root)`。
3. 等待 GitHub Pages 顯示 HTTPS 網址後，以手機 Chrome 開啟該網址。
4. 在 Chrome 點右上角 `⋮`，選擇「安裝應用程式」或「加入主畫面」，再確認安裝。

從主畫面開啟後，首次仍請保持網路正常，讓應用殼層完成快取。

### Android 最後人工驗收

1. 從手機主畫面啟動 Meowney，確認沒有瀏覽器網址列且帳戶、交易、設定可正常顯示。
2. 建立至少兩筆勾選「預計請款」的同帳戶支出、一筆收入、一筆部分報銷支出與一筆轉帳；在查詢選取兩筆建立合併報銷，核對只新增一筆合計報銷收入、備註列出兩個項目、帳戶餘額增加合計金額，且兩筆原支出取消預計請款。報銷支出應產生可獨立修改金額的「報銷」收入，並自動取消原支出的預計請款與請款單；修改原支出金額不應改變報銷金額，刪除原支出應一併移除報銷。
3. 在「查詢」組合日期、帳戶、類別、類型、請款狀態、備註與金額範圍，確認尚未請款、統計與清單同步更新。
4. 匯出 JSON，並確認 CSV 預覽與匯入確認畫面顯示正確筆數。
5. 完全關閉應用、開啟飛航模式，從主畫面重新啟動；確認可查看、新增、修改、刪除、查詢與管理資料。
6. 在新增與編輯面板中開啟軟體鍵盤，確認金額、確定按鈕、Bottom Sheet 與底部導覽沒有被遮住。

## 資料復原演練

1. 匯出 JSON 備份，保留原始檔。
2. 在另一個乾淨瀏覽器設定檔或清除後的網站資料中開啟應用。
3. 從「設定」選取該 JSON，確認完整覆蓋警告。
4. 核對帳戶餘額、已刪除帳戶／類別的歷史名稱、轉帳與查詢結果。

## 開發期測試

執行 `pnpm test` 可跑全部資料完整性與交付檢查。`fake-indexeddb` 只存在於 `devDependencies`，只供測試在 Node 環境模擬瀏覽器資料庫；正式應用不會引用或打包它。

已於目標 Android Chromium 驗收 PWA 安裝、飛航模式重新啟動與手機實際觸控流程。
